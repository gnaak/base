구글 로그인 키 받기

"Google 로 시작하기" 버튼이 동작하려면 구글 클라우드에 내 서비스를 등록하고 키 두 개(클라이언트 ID · 시크릿)를 받아야 해요. 로그인 기능 자체는 이미 만들어져 있어요.

  • 15~20분
  • 필요: 구글 계정
  • 무료 (결제 정보 필요 없음)
메뉴 이름이 바뀌었어요

예전 글의 "OAuth 동의 화면(OAuth consent screen)" 은 지금 Google Auth Platform 하나로 합쳐져 있고, 안에 Branding · Audience · Data Access · Clients 탭이 있어요.

순서

  1. 프로젝트 만들기 console.cloud.google.com 에 로그인 → 위쪽 프로젝트 선택 → 새 프로젝트 → 서비스 이름으로 만들어요.
  2. Google Auth Platform 시작 왼쪽 메뉴 APIs & Services → Google Auth Platform → Get started. 앱 이름 · 지원 이메일을 적고, 사용자 유형은 External(외부) 을 골라요 — 나중에 못 바꿔요. 회사 Google Workspace 안에서만 쓸 때만 Internal.
  3. 받을 정보(Data Access) Data Access 탭 → Add or remove scopes → openid · .../auth/userinfo.email · .../auth/userinfo.profile 세 개를 체크하고 저장해요.
  4. 키 만들기(Clients) Clients 탭 → Create Client → Application type 은 Web application → Authorized redirect URIs 에 아래 주소를 추가 → Create. 
    http://localhost:3000/google/login
    서버에 올린 뒤에는 https://내도메인/google/login 도 한 줄 더 추가해요.
  5. 키 확인 — 시크릿은 지금 저장 "OAuth client created" 창에 Client ID 와 Client secret 이 떠요. 시크릿은 나중에 다시 전체를 못 볼 수 있으니 Download JSON 으로 받아 두거나 바로 6번을 해요.
  6. 키를 설정 파일에 적기 — 대화창에 붙여 넣지 마세요 Claude 에게 "구글 키 받았어요" 라고 하면 설정 파일 두 개를 메모장으로 열고 몇 번째 줄인지 알려 줘요.
    파일줄넣을 값
    backend/.envgoogle_client_id=Client ID
    backend/.envgoogle_client_secret=Client secret
    frontend/.envVITE_APP_PUBLIC_GOOGLE_CLIENT_ID=Client ID (위와 같은 값)
"Testing" 그대로 둬도 돼요

Audience 탭에 상태가 Testing 으로 나와요. 이 서비스는 이름 · 이메일 · 프로필(기본 정보)만 받아서, Testing 이어도 누구나 로그인할 수 있고 7일 만료도 걸리지 않아요. 동의 화면에 앱 이름 · 로고가 깔끔하게 나오길 원하면 Branding 을 채우고 Publish app — 기본 정보만 받으면 구글 심사도 없어요.

막히면

  • Error 400: redirect_uri_mismatch — 등록한 주소와 실제 주소가 달라요. http / https, 끝의 /, 포트까지 똑같은지 봐요
  • 방금 고쳤는데 그대로 mismatch — 구글은 반영까지 5분에서 몇 시간 걸려요. 잠시 뒤에 다시 해요
  • "Google hasn't verified this app" 경고 — 3번에서 기본 세 개 말고 다른 범위를 골랐는지 봐요
  • Google Auth Platform 메뉴가 안 보여요 — 위쪽 검색창에 "Google Auth Platform" 을 쳐요
서버에 올릴 때

운영 서버의 키는 이 파일이 아니라 AWS Parameter Store 에 넣어요 (infra/README.md 의 "OAuth · 외부 API 키"). 그리고 4번의 redirect URI 에 https://내도메인/google/login 을 추가해요.
