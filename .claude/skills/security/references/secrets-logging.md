# 시크릿 · 로그 · 노출

목표: 키가 저장소·로그·응답으로 새지 않고, 운영에서 내부 정보가 보이지 않는다.

## 체크리스트

### 시크릿
- [ ] 코드·테스트·문서에 실제 키가 없다 — Grep: `sk_live`, `secret.*=.*['"][A-Za-z0-9]{16,}`, `AKIA`, `-----BEGIN`
- [ ] `.env`·`.env.*` 가 `.gitignore` 에 있고 추적되지 않는다 (`git ls-files | grep .env` 는 `.env.example` 만)
- [ ] `jwt_secret` 이 비었거나 짧으면 기동을 거부한다 (32자 미만이면 ❌ — 빈 값이면 누구나 토큰을 만든다)
- [ ] 새 설정 키는 `RawEnv` 필드 + `.env.example` + (운영) SSM 이름이 같다
- [ ] 브랜치·백업 브랜치에 옛 `.env` 가 남아 있지 않은지 (`git log --all -- backend/.env`) — 있으면 푸시 금지 ⚠️

### 로그
- [ ] 요청·응답 헤더 전문, Authorization, 쿠키, 비밀번호, 카드·빌링키를 로그에 남기지 않는다
- [ ] 이메일·전화·주소·채팅 본문 같은 개인정보를 info 로그에 남기지 않는다 — ⚠️ (필요하면 마스킹)
- [ ] 쿼리스트링의 민감 키는 마스킹된다 (`middleware/request_id.py`)

### 노출
- [ ] **운영에서 `/docs`·`/redoc`·`/openapi.json` 이 닫혀 있다** — 열려 있으면 전체 API 지도가 공개된다 (⚠️, 관리자 API 가 있으면 ❌)
- [ ] 미처리 예외는 일반 500 메시지만 준다 (스택은 로그로)
- [ ] `fail()` 메시지에 내부 정보(쿼리, 경로, 업체 원문)를 넣지 않는다 — `fail()` 의 message 는 그대로 클라이언트로 간다
- [ ] 회원가입 409·로그인 시간차로 이메일 존재를 알 수 있는지 — ⚠️ (서비스 성격에 따라)
- [ ] 비밀번호 최대 길이가 있다 — 없으면 argon2 해싱에 거대한 입력으로 CPU 를 태울 수 있다 (⚠️)
