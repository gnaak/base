입력: `PRD/02_PRD.md`(승인), `PRD/00_brief.md`("결정" 절 — 고른 디자인 방향 등), `PRD/01_research/ux.md`,
`PRD/01_research/design.md`, 템플릿 라우트(`frontend/src/App.tsx`). 재작성이면 기존 `03_PAGE.md` + reviewer 펀치리스트.
출력: `PRD/03_PAGE.md` 하나만 쓴다.

## 원칙

- **페이지 맵은 "결정"이다** — 어떤 화면이 있고, 화면마다 무엇이 들어가고, 어디서 와서 어디로 가는지.
  레이아웃·간격·색 같은 시각 디테일은 쓰지 않는다 (디자인은 `04_DESIGN.md`, 구현은 fe-ui-builder)
- **UI 패턴은 템플릿에 있든 없든 그 화면에 필요한 것을 쓴다** — "플랜 카드 목록", "주간 메뉴 사진 갤러리",
  "하단 탭"처럼. 템플릿 컴포넌트 이름에 맞추지 않는다. 만들지 재사용할지는 design-writer 와 fe-ui-builder 가 정한다
- **must F-ID 는 전부 어딘가에 있어야 한다.** 화면이 없는 기능(자동결제 배치 등)은 4장에 "결과가 보이는 곳"과 함께
- **PRD 완료 기준에 단계 수·흐름이 있으면 그대로 맞춘다** (예: "해지는 2단계"면 3장 흐름도 2단계)
- **대상을 섞지 않는다** — 한 페이지는 비로그인 / 주민(`user_` 세션) / 사장님 / 관리자(`admin_` 세션) 중 하나.
  비로그인이 보는 페이지에 로그인 후 기능이 붙으면 "로그인 시" 로 표시한다
- **PRD 에 없지만 있어야 하는 화면**(로그인, OAuth 콜백, 404, 약관·처리방침)은 넣고 `(전제 페이지)` 로 표시한다
- **템플릿 라우트와 겹치지 않게** — `frontend/src/App.tsx` 를 읽어 지금 있는 경로(`/`, `/admin`, `/admin/login`,
  `/google/login`, `/kakao/login`, `/mypage` 등)를 확인하고, 재사용이면 "템플릿 재사용", 바꾸면 "교체"로 적는다.
  관리자 화면은 `/admin/**` 아래, 사이드바 메뉴 구성으로 묶는다

## `03_PAGE.md` 형식

```markdown
# 페이지 맵: [가칭]
> 작성일: YYYY-MM-DD · 근거: 02_PRD.md(승인), 01_research/ux.md · 상태: 초안

## 1. 페이지 목록
| P-ID | 페이지 | 라우트 | 대상 | 포함 F-ID | 진입 경로 | 다음 페이지 | 필요한 UI 패턴 | 템플릿 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| P1 | 가게 목록 | / | 비로그인 | F6 | 첫 진입 | P2 | 가게 카드 목록 | 교체(`/` ClientMain) |

## 2. 페이지 트리
(대상별 — 주민 / 사장님 / 관리자. 관리자는 사이드바 메뉴 그룹 기준)

## 3. 핵심 흐름
### 흐름 1: [이름] (F7)
P4 → P5 → (PG 카드 창) → P6 = N단계 — PRD F7-1 과 맞음
(PRD 에 단계 수가 있는 흐름은 반드시. 화면 밖 단계(PG 창·카카오 동의)도 단계로 센다)

## 4. 화면 없는 기능
| F-ID | 무엇 | 결과가 보이는 곳(P-ID) |

## 5. F-ID 커버리지
| F-ID | 우선순위 | P-ID |
(must 전부 + should 는 화면이 정해진 것만)
```

표 셀 안에서는 줄바꿈하지 않는다.

## 메인에게 반환할 것

- 파일 경로, 페이지 수(대상별), 흐름 수
- 커버리지: must F-ID 중 화면 없음으로 남은 것(4장) 목록
- 전제 페이지로 추가한 것, 템플릿 라우트를 교체하는 것
