호출자가 phase 번호를 준다 (없으면 `PROGRESS.md` 에서 🔄 진행중, 그것도 없으면 가장 최근 ✅ 완료 phase).

## 할 일

1. `PROJECT.md` 에서 그 phase 의 **완료 기준**(`- [ ] F3-2 …`)과 **개발에서 다룰 것**을 읽는다.
   각 기준의 원문은 `PRD/02_PRD.md` 5장에서 ID 로 다시 확인한다 (PROJECT.md 가 바꿔 썼으면 그 자체를 ⚠️ 로)
2. 기준마다:
   - **구현**을 찾는다 — 그 동작을 만드는 라우터·서비스·컴포넌트 (`파일:줄`)
   - **테스트**를 찾는다 — 그 기준을 단언하는 테스트 (`backend/tests/`, `frontend/src/**/*.test.*`, `frontend/e2e/`).
     테스트 이름·단언문이 기준의 입력과 기대 결과를 실제로 확인하는지 본다 (이름만 비슷하면 안 된다)
   - 판정:
     | 판정 | 뜻 |
     | --- | --- |
     | ✅ 충족 | 구현이 있고, 그 기준의 입력→기대 결과를 단언하는 테스트가 있다 |
     | 🟡 테스트 없음 | 구현은 보이는데 그 기준을 단언하는 테스트가 없다 |
     | ❌ 미충족 | 구현이 없거나, 구현이 기준과 다르게 동작한다 (어디가 다른지) |
3. "개발에서 다룰 것" 항목마다 테스트로 덮였는지 본다 (완료 기준은 아니라 ⚠️ 만)
4. 그 phase 의 **설정값**(U*) 줄이 있으면 해당 값이 `settings`(`RawEnv`)에서 읽히는지, 코드에 숫자로 박혀 있지 않은지 본다 — 박혀 있으면 ❌

## 보고

```
## 완료 기준 대조: phase N — [이름]

| ID | 판정 | 구현 | 테스트 | 메모 |
| --- | --- | --- | --- | --- |
| F3-1 | ✅ | order_service.py:42 | test_order_router.py::test_… | |
| F3-2 | 🟡 | order_router.py:18 | — | 남의 주문 404 를 단언하는 테스트 없음 |

충족 a / 테스트 없음 b / 미충족 c
개발에서 다룰 것: 덮임 x / 안 덮임 y (목록)
설정값: 확인 결과
```

**읽기 전용** — 테스트를 쓰거나 코드를 고치지 않는다. 판정 근거가 애매하면 🟡 로 두고 이유를 적는다.
